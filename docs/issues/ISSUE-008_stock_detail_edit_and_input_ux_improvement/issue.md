## 📌 課題の概要・背景 (Problem Description / Context)

現在の MyHomeStock アプリケーションにおいて、以下の 3 つの UI/UX 上の重大な課題・操作性のボトルネックが存在している：

1. **在庫アイテムの詳細編集が一覧からできない**:
   - バックエンド API（`PUT /api/v1/stocks/{id}`）およびカスタムフック（`useUpdateStock`）は完成しているが、UI 上に編集モーダル（EditStockModal）が存在せず、登録後に品名、カテゴリ、数量、単位、最小閾値、賞味期限、メモを編集・変更する手段がない（現在は `+` / `-` と削除のみ）。
2. **日用品と消耗品の境界が曖昧で登録時に迷う**:
   - 選択肢に「日用品」と「消耗品」が分かれて存在しているが、一般家庭での境界が曖昧であり、登録時にどちらを選ぶべきか認知負荷・混乱を招いている。
3. **賞味期限を一度入力すると空（未設定）に戻せない**:
   - `<input type="date">` を直接使用しており、一度日付を入力すると「期限なし」にクリアするボタンがないため、日用品や長期保存品などで賞味期限を管理したくない場合に困る。

---

## 🎯 要件定義 (Requirements)

1. **在庫詳細編集モーダル (`EditStockModal.tsx`) の実装**:
   - 在庫一覧カード、買い物リスト、期限管理リストの各カードに「編集（ペンアイコン）」ボタンを配置。
   - クリック時にモーダルを開き、全項目（品名、カテゴリ、数量、単位、最小閾値、賞味・消費期限、メモ）を編集可能にする。
   - 保存時に `useUpdateStock()` を呼び出し、JPA 楽観的排他制御（`version`）をバインドして安全に更新。
   - 競合検知（HTTP 409 Conflict）時は「他端末で更新されました」と通知し、最新データを再取得する。
2. **カテゴリの整理・統合**:
   - 「日用品」と「消耗品」を **「日用品・消耗品」** に統合。
   - カテゴリ選択肢の標準構成: `食品`, `飲料`, `日用品・消耗品`, `医薬品`, `その他`。
   - クイック追加フォームおよび編集モーダル、カテゴリフィルターの選択肢を一元化。
3. **賞味期限のクリア機能（期限なしボタン）**:
   - クイック追加フォームおよび詳細編集モーダルの賞味期限入力欄に「クリア（×）」ボタン（または「期限なし」バッジ/ボタン）を配置。
   - ワンタップで日付入力欄を空文字（未設定）に戻せるようにする。

## 🛠️ 技術設計・実装方針 (Technical Notes / Design)

- **フロントエンド**:
  - `frontend/src/components/stock/EditStockModal.tsx`: 詳細編集モーダルコンポーネント新設。
  - `frontend/src/App.tsx`: 各カードへの編集ボタン配置、モーダル開閉ステート管理、カテゴリ定義の統合、期限入力欄のクリアボタン配置。
  - `frontend/src/constants/categories.ts`: カテゴリ定義の一元管理（重複防止）。
- **バックエンド**:
  - バックエンド API `PUT /api/v1/stocks/{id}` は既に稼働中。スキーマ変更は不要。
