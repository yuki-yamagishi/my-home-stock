# [ISSUE-008] 在庫詳細編集モーダル（EditStockModal）の実装と入力UI/UX改善

* **ステータス**: 🟠 `status: in-progress`
* **種別**: 🟢 `type: feature` / 🎨 `type: ui/ux`
* **担当者**: AIエージェント
* **作成日**: 2026-09-14
* **関連 ADR / GitHub Issue**: GitHub Issue #9 / ISSUE-002

---

## 1. 解決すべき課題・背景 (Why / Background)

現在稼働中の MyHomeStock Web/PWA アプリケーションにおいて、以下の 3 つの操作性ボトルネックおよびユーザー体験上の課題が存在する：

1. **登録済み在庫アイテムの詳細編集が UI から不可能**:
   - バックエンド REST API（`PUT /api/v1/stocks/{id}`）および TanStack Query カスタムフック（`useUpdateStock`）による JPA 楽観排他更新基盤は完成しているが、フロントエンド UI 上に詳細編集モーダルが存在しない。
   - そのため、登録後に品名誤字、カテゴリ変更、単位修正、下限閾値の見直し、賞味期限の更新、保管場所メモの追記などを行う手段がなく、一度削除して再登録する運用を強いられている。
2. **「日用品」と「消耗品」の境界が曖昧で登録時に迷う**:
   - 選択肢に「日用品」と「消耗品」が分かれて存在しているが、一般家庭での境界（洗剤、ティッシュ、ラップ等は日用品か消耗品か）が曖昧であり、在庫登録およびフィルタリング時に認知負荷と分類のブレが生じている。
3. **賞味期限を一度入力すると空（未設定）に戻せない**:
   - 日付入力欄（`<input type="date">`）にクリア手段が存在しないため、誤って賞味期限を入力してしまったり、賞味期限管理が不要になった場合に「期限なし」に戻すことができない。

---

## 2. 排除するリスク (Risks to Eliminate)

1. **同時編集によるデータ先祖返りリスク（排他制御抜けの防止）**:
   - 複数端末（家族間）で同一アイテムを同時に詳細編集した場合に、後勝ちでデータが上書きされてしまうリスクを排除する。編集モーダルから送信する更新 DTO に `@Version`（`version`）を確実にバインドし、409 Conflict 検知時に警告を表示して最新データを再取得する。
2. **旧カテゴリ保持アイテムの意図せぬカテゴリ破壊リスク（先頭オプション上書き防止）**:
   - データベース内に「日用品」または「消耗品」として登録されている既存アイテムを編集モーダルで開いた際に、選択肢不一致によって先頭カテゴリ（「食品」等）へ自動上書きされてしまうリスクを排除する。旧カテゴリ「日用品」「消耗品」を自動的に「日用品・消耗品」へマッピングして初期選択する正規化ロジックを配備する。
3. **カテゴリ不整合・認知負荷リスクの排除**:
   - 「日用品」と「消耗品」を「日用品・消耗品」に統合し、定数を一元管理することで、UI コンポーネント間（登録フォーム、編集モーダル、フィルタータブ）での表記揺れや選択肢乖離を物理的に防止する。
4. **UI 状態の不整合・クリア不能リスクの排除**:
   - 賞味期限を未設定に戻すワンタップクリア操作を配備し、日付フォーマット（空文字 `""` から `undefined` / `null` への正規化）の不整合による API エラーを排除する。

---

## 3. 要件定義 (Requirements)

1. **在庫詳細編集モーダル (`EditStockModal.tsx`) の新設**:
   - 在庫カード（および買い物・期限リストカード）に編集アイコンボタン（Pencil）を配置。
   - クリック時にモーダルを展開し、品名、カテゴリ、数量、単位、最小閾値、賞味期限、メモの全項目を編集可能にする。
   - 品名が空文字または空白のみの場合は保存ボタンを非活性化（disabled）し、無効な更新 API 送信を抑止する。
   - 更新時は `useUpdateStock()` を実行し、排他制御バージョン番号（`version`）を含めて `PUT /api/v1/stocks/{id}` を呼び出す。
   - 更新成功時はモーダルを閉じ、最新在庫一覧を TanStack Query キャッシュ無効化により再取得する。
   - キャンセルボタン、ESC キー押下、またはオーバーレイクリック時は変更を破棄してモーダルを閉じる。
2. **カテゴリ定義の一元化と旧カテゴリ自動移行**:
   - カテゴリ定数を `frontend/src/constants/categories.ts` に集約。
   - 標準カテゴリ構成: `食品`, `飲料`, `日用品・消耗品`, `医薬品`, `その他`。
   - カテゴリ正規化関数 `normalizeCategory(category: string): StockCategory` を実装。旧「日用品」および「消耗品」は「日用品・消耗品」に安全に初期マッピングされる。
   - クイック追加フォーム、編集モーダル、および一覧フィルターで同一の定数を参照する。
3. **賞味・消費期限のワンタップクリア機能**:
   - 日付入力欄の横にクリアボタン（`×` アイコン）を配置。
   - クリック時に日付値を空文字にし、期限なし状態へ即座に復帰可能にする。

---

## 4. 技術設計・実装方針 (Technical Notes / Design)

- **フロントエンド構成**:
  - `frontend/src/constants/categories.ts`: カテゴリ一覧・デフォルト値の一元定義、および旧カテゴリ正規化関数（`normalizeCategory`）。
  - `frontend/src/components/stock/EditStockModal.tsx`: 詳細編集モーダルコンポーネント。アクセシビリティ（ESC キー閉じ、背景スクロール固定、フォーカストラップ）に配慮。
  - `frontend/src/App.tsx`: 編集対象アイテム（`editingItem: StockItem | null`）のステート管理、各カードへの編集ボタン配置、期限クリアボタン配置、カテゴリ定数インポート。
- **排他制御ハンドリング**:
  - `useUpdateStock` の既存エラーハンドラー（409 Conflict 検知時のアラートとキャッシュ無効化）と連動し、モーダル側でも保存中フラグ（`isPending`）によるボタン非活性化を徹底。

## 5. 受け入れ基準 (Acceptance Criteria & DoD)

### 5.1. 機能受け入れシナリオ (Given-When-Then)

- **シナリオ 1: 詳細編集モーダルの起動と初期値表示**:
  - **Given**: 在庫一覧に「牛乳（カテゴリ: 食品, 数量: 2, 単位: 本, 閾値: 1, 期限: 2026-09-30, メモ: 低脂肪）」が存在する。
  - **When**: 当該アイテムのカード内にある「編集」ボタンをクリックする。
  - **Then**: 詳細編集モーダルが開き、入力欄に現在のすべての値が初期セットされて表示される。

- **シナリオ 2: 項目変更と保存（楽観排他制御）**:
  - **Given**: 詳細編集モーダルが開いている。
  - **When**: 数量を「5」、メモを「まとめ買い」に変更して「更新する」ボタンをクリックする。
  - **Then**: `PUT /api/v1/stocks/{id}` がバージョン番号付きで送信され、保存成功後にモーダルが閉じ、一覧の表示が数量「5」、メモ「まとめ買い」に更新される。

- **シナリオ 3: 同時編集時の 409 Conflict 検知**:
  - **Given**: 詳細編集モーダルで編集作業を行っている間に、別端末で数量が変更された。
  - **When**: 「更新する」ボタンをクリックする。
  - **Then**: 409 Conflict が返却され、警告メッセージが表示されて最新データが再同期される。

- **シナリオ 4: カテゴリ統合（日用品・消耗品）**:
  - **Given**: クイック追加フォームおよび詳細編集モーダルを開く。
  - **When**: カテゴリドロップダウンを表示する。
  - **Then**: 「日用品」「消耗品」の重複選択肢はなく、「日用品・消耗品」が単一の選択肢として提供されている。

- **シナリオ 5: 賞味期限のクリア**:
  - **Given**: 賞味期限が「2026-09-30」と入力されている。
  - **When**: 期限入力欄横のクリアボタンをクリックする。
  - **Then**: 日付値が未設定（空文字）になり、そのまま保存すると期限なしとして登録・更新される。

- **シナリオ 6: 品名空文字時のバリデーション拒絶（API送信抑止）**:
  - **Given**: 詳細編集モーダルが開いている。
  - **When**: 品名入力欄を全削除して空文字（または空白文字のみ）にする。
  - **Then**: 「更新する」ボタンが非活性化（disabled）され、Enter キーやボタン押下による不正な更新 API リクエストの送信が阻止される。

- **シナリオ 7: 旧カテゴリ保持アイテムの安全な編集（カテゴリ破壊防止）**:
  - **Given**: 既存の在庫アイテムに旧カテゴリ「日用品」または「消耗品」が設定されている。
  - **When**: 当該アイテムの「編集」ボタンをクリックして詳細編集モーダルを開く。
  - **Then**: カテゴリ選択欄において「日用品・消耗品」が自動的に選択状態となり、意図せず先頭オプション（「食品」等）に化けることなく安全に編集・保存できる。

- **シナリオ 8: 編集のキャンセルと変更破棄**:
  - **Given**: 詳細編集モーダルで数量を「10」に変更した。
  - **When**: キャンセルボタンをクリック、または ESC キーを押下、またはモーダル外オーバーレイをクリックする。
  - **Then**: モーダルが閉じ、更新 API は実行されず、一覧カードの表示は元の数量のまま維持される。
