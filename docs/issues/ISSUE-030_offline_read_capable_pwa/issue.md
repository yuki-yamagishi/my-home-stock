# [ISSUE-030] 直前キャッシュによるオフライン閲覧保証（Pragmatic Offline-Read）と ADR-002 是正

* **ステータス**: 🟣 `status: in-progress`
* **種別**: 🟢 `type: feature` / 🛡️ `type: security` / 📚 `type: docs`
* **担当者**: AIエージェント
* **作成日**: 2026-10-03
* **関連 GitHub Issue / PR**: [GitHub Issue #30](https://github.com/yuki-yamagishi/my-home-stock/issues/30) / ADR-0002

---

## 1. 解決すべき課題・背景 (Why)

1. **スーパーの地下や圏外環境における買い物リスト閲覧不能の解消**:
   - 日常の在庫管理やスーパーでの買い物中、地下食品売り場や大型店舗奥など電波の届かない場所で買い物リストを確認したいという強いニーズがある。
   - しかし現状の実装（`vite.config.ts`, `main.tsx`）では、Service Worker による静的アセット（HTML/JS/CSS）のプリキャッシュしか行われておらず、API データ（在庫一覧・買い物リスト）のローカル永続化が一切存在しない（インメモリキャッシュ `staleTime: 5000` のみ）。
   - さらに、アプリ起動時の Google OAuth2 認証チェック（`GET /api/v1/auth/me`）がオフライン時に通信失敗（`Failed to fetch`）すると、`useAuth.ts` が未認証と判定して `LoginCard`（Google ログイン画面）へ強制遷移させてしまう。
   - このため、地下でアプリを起動したり画面をリロードした瞬間に、在庫一覧や買い物リストが 1 件も閲覧できなくなる致命的な UX 欠陥が存在する。

2. **ADR-002 の誇大表現と実装の乖離の是正**:
   - `docs/adr/0002-pwa-mobile-offline-first.md` では「PWA によるオフラインファースト戦略」「地下でも素早く確認・更新できる」と誇大に記載されているが、実際の実装は完全なオンライン前提であり、オフラインでの更新（Mutation）はネットワークエラーで即座に失敗し、キューイングも楽観的更新も存在しない。
   - ドキュメントと実装の重大な乖離（グローバル憲章第 1.1 条・第 1.2 条違反）を解消し、誇大看板を下ろして実態と同期させる必要がある。

3. **セキュリティ境界と排他制御（ADR-0003）の保護**:
   - ローカルストレージへのデータ永続化を行うにあたり、ログアウト後もデータが残存したり、世帯除外後もデータが見え続けるセキュリティリスクを排除しなければならない。
   - また、オフライン中の操作を許可するとサーバーの `@Version` 楽観排他制御（ADR-0003）との競合が頻発するため、オフライン時は閲覧（Read-Only）に特化させ、更新操作を物理的に無効化（Disabled）することでデータ整合性を担保する。

## 2. 排除するリスク (Risks to Eliminate)

1. **オフライン起動時の認証遮断・ログイン画面送還リスクの排除**:
   - 通信エラー（`TypeError: Failed to fetch`）とサーバー拒絶（`HTTP 401 Unauthorized`）を明確に区別し、直前の有効な認証プロファイル（24時間以内）が存在する場合は閲覧専用ダッシュボードへ遷移させる。
2. **共用端末やログアウト後におけるローカルキャッシュ情報漏洩リスクの排除**:
   - ログアウト実行時および `401 Unauthorized`（セッション失効）検知時に、ローカルストレージ（IndexedDB / localStorage）を 1 バイト残らず物理破棄（Purge）する。
3. **オフライン中の誤操作によるデータ競合・サイレントエラーリスクの排除**:
   - オフライン時は画面上部に「⚠️ オフライン表示中」バナーを表示し、更新系ボタン（購入完了、数量変更、消費、追加、削除）を物理的に `disabled` 化して、サーバーとの不整合・409 Conflict の無駄な発生を未然に防止する。
4. **古いデータの永久残存リスクの排除**:
   - キャッシュの有効期限（TTL: 24時間）を設定し、期限切れキャッシュは自動的に破棄して再認証を要求する。

## 3. 受け入れ基準 (Acceptance Criteria / DoD)

- [x] TanStack Query Persister（`createSyncStoragePersister` または IndexedDB）が導入され、在庫一覧・買い物リストのクエリ結果がローカルに永続化されること。
- [x] キャッシュの最大保持期間（`maxAge: 24 * 60 * 60 * 1000` = 24時間）が設定され、24時間経過後はキャッシュが無効化されること。
- [x] ネットワーク切断時（機内モードまたはオフライン時）にアプリをリロード・再起動しても、直前に取得した在庫一覧および買い物リストが即座に表示されること。
- [x] オフライン閲覧中である場合、画面上部に「⚠️ オフライン表示中 (最終同期: HH:mm) - 電波復帰時に自動更新されます」バナーが表示されること。
- [x] オフライン閲覧中は、更新系ボタン（購入完了、数量プラス、消費マイナス、残量変更、新規在庫追加、編集、削除）が `disabled` となり、誤操作が防止されること。
- [x] 電波復帰時（`online` イベント発火時）にバックグラウンドで最新実データが自動再取得（Refetch / SWR）され、オフラインバナーが自動消去され、ボタンが活性化されること。
- [x] ユーザーが「ログアウト」を実行した場合、TanStack Query のメモリキャッシュおよび永続化ストレージのデータが完全に消去されること。
- [x] オンライン復帰時にサーバーから `HTTP 401 Unauthorized` が返却された場合、ローカルキャッシュが即座に完全消去され、ログイン画面へ遷移すること。
- [x] `docs/adr/0002-pwa-mobile-offline-first.md` が改定され、「オフライン閲覧保証（Pragmatic Offline-Read）」として再定義されていること。
- [x] `frontend/tests/` 配下にオフライン状態検知、キャッシュ永続化、認証フォールバック、ログアウト時消去の単体テストが追加され、全件 PASS すること。
- [x] `npm.cmd run check`（シークレット、ドキュメント整合性、型検査、テスト全件、プロダクションビルド）が 100% 合格すること。

## 4. 機能受け入れシナリオ (Given-When-Then & 境界値・異常系)

### シナリオ 1: オフライン起動時の直前キャッシュ閲覧（正常系）
- **Given**: ユーザーがオンライン環境でログイン済みであり、在庫アイテム 5 件と買い物リスト 2 件を取得してローカルキャッシュ（取得から10分前）が保持されている。
- **When**: 端末を機内モード（オフライン）にし、ブラウザでアプリをリロードする。
- **Then**:
  - `GET /api/v1/auth/me` の通信失敗が発生するが、直前の有効な認証キャッシュによりログイン画面には飛ばされない。
  - 画面上部に「⚠️ オフライン表示中 (最終同期: XX:XX)」バナーが表示される。
  - 在庫アイテム 5 件および買い物リスト 2 件が即座に画面に表示される。
  - 「購入完了 (+1)」や「1段階消費」ボタンが `disabled` 状態になっている。

### シナリオ 2: 電波復帰時の自動再同期（正常系）
- **Given**: シナリオ 1 のオフライン閲覧状態で画面を開いている。
- **When**: 端末の機内モードを解除し、オンライン（電波復帰）にする。
- **Then**:
  - `online` イベントを検知し、TanStack Query がバックグラウンドで `/api/v1/stocks` および `/api/v1/auth/me` を自動再取得する。
  - サーバーの最新データで画面が上書き更新される。
  - 「⚠️ オフライン表示中」バナーが自動的に非表示になり、更新系ボタンが活性化（enabled）される。

### シナリオ 3: ログアウト時のローカルストレージ物理消去（セキュリティ境界）
- **Given**: オンライン環境で在庫データおよび買い物リストがキャッシュされている。
- **When**: ユーザーがヘッダーのユーザーメニューから「ログアウト」を実行する。
- **Then**:
  - サーバーの `/api/v1/auth/logout` が呼び出される。
  - ブラウザの localStorage / IndexedDB 内の TanStack Query 永続化データおよび認証情報が完全に消去（`removeItem` / `clear`）される。
  - 画面がログインカードに遷移し、その後オフラインになっても古い在庫データは一切表示されない。

### シナリオ 4: セッション失効（401）時の自動消去（セキュリティ異常系）
- **Given**: 端末にキャッシュが残っている状態で電波が復帰した。
- **When**: サーバーのバックグラウンド再取得で `HTTP 401 Unauthorized`（他端末でのログアウトやセッション期限切れ）が返却される。
- **Then**:
  - ローカルキャッシュが直ちに完全破棄される。
  - 即座にログイン画面に遷移し、古いデータの閲覧が遮断される。

### シナリオ 5: キャッシュ TTL 期限切れ（境界値系）
- **Given**: 最終オンライン同期から 24 時間と 1 分が経過した古いキャッシュが存在する。
- **When**: 端末がオフラインの状態でアプリを起動する。
- **Then**:
  - キャッシュは TTL（24時間）切れと判定され、読み込みが拒絶される。
  - 画面には古いデータは表示されず、「オフラインのため再接続が必要です」と表示される。

## 5. 技術的アプローチ・設計方針

1. **キャッシュ永続化アーキテクチャ**:
   - `@tanstack/react-query-persist-client` + `createSyncStoragePersister` を使用し、Web Storage（localStorage）に安全にシリアライズ・保存する。
   - `buster` キーにアプリバージョン（ビルドハッシュ等）を設定し、フロントエンドの更新時に古いキャッシュ構造が自動破棄されるようにする。
   - `maxAge` を `24 * 60 * 60 * 1000`（24時間）に設定。
2. **ネットワーク状態とオフライン閲覧の判定フック**:
   - `useNetworkStatus.ts` を新設し、`navigator.onLine` および `online`/`offline` イベントをリッスン。
   - 最終同期時刻（`lastSyncedAt`）を TanStack Query のキャッシュ成功時に記録。
3. **認証状態のオフラインフォールバック**:
   - `useAuth.ts` において、`queryFn` の失敗時に `error instanceof ApiError && error.status === 401` でない（ネットワーク切断によるエラー）場合、ローカルに保持された `lastAuthUser` を返却して認証状態を維持する。
4. **UI ガード**:
   - `Header.tsx` または `App.tsx` 直下に `OfflineBanner.tsx` を配置。
   - 各操作ボタンに `disabled={!isOnline}` またはツールチップを適用。
