# [ISSUE-012] 買い物リストのカテゴリ別表示・絞り込み導入および在庫管理画面の重複追加ボタン整理

* **ステータス**: ✅ `status: closed`
* **種別**: 🟢 `type: feature` / 🎨 `type: ui/ux`
* **担当者**: AIエージェント
* **作成日**: 2026-09-17
* **関連 GitHub Issue**: ISSUE-012

## 1. 解決すべき課題・背景 (Why / Background)

1. **在庫管理画面における追加導線の重複と横スクロール領域の圧迫**:
   - ISSUE-011 でモバイル向けに右下フローティングアクションボタン（FAB: `+`）が導入された。
   - しかし、在庫管理画面（Stocks List）上部のカテゴリフィルター横に配置された「在庫を追加」ボタン（`Button`）に `hidden sm:flex` が設定されておらず、モバイル画面でカテゴリピルの横に固定表示されたままとなっていた。
   - 画面幅が狭いスマートフォン（360px〜400px）において、このボタンが横幅の大半を占有し、カテゴリピルの可視領域を著しく狭めて横スクロールの快適性を阻害していた。
   - 一方で、買い物リスト画面の上部ボタンは既に `hidden sm:flex` となっており、画面ごとのレスポンシブ挙動にも不整合が生じていた。

2. **買い物リスト画面におけるカテゴリ別一覧性の欠如**:
   - 買い物リスト画面では、不足している在庫品目が単一のグリッドに平坦に羅列されており、カテゴリ情報（食品、日用品・消耗品、医薬品等）は各カード内の小さなラベルとして表示されるのみであった。
   - スーパーやドラッグストアでの買い出し時に、売り場（カテゴリ）ごとに何を買うべきかが一目で把握できず、「食品売り場にいるのに日用品と混ざって見落とす」「売り場を行ったり来たりする」といった実生活上のストレス・非効率が発生していた。

---

## 2. 排除するリスク (Risks to Eliminate)

1. **モバイル／デスクトップ間の操作性トレードオフ・在庫追加導線喪失リスクの排除**:
   - モバイル表示時（`< sm`）は右下の固定FABに導線を一本化し、カテゴリ横の重複ボタンを非表示化することでカテゴリ選択エリアを最大化する。
   - 一方、デスクトップ表示時（`sm:` 以上）はFABが非表示となるため、カテゴリフィルター横の上部ボタン（`hidden sm:flex`）を維持し、PCユーザーが迷わず在庫追加できるようにする。
2. **純粋コアロジックの不可侵・React結合リスクの排除**:
   - 買い物リストのカテゴリ別グルーピング・ソート・フィルタリング処理を React コンポーネント内にインラインでつぎはぎ実装（パッチワーク）せず、`frontend/src/core/` 配下に純粋関数として分離・実装する。
   - UI/DOM非依存の純粋関数として Vitest で 100% 単体テストを網羅し、保守性と堅牢性を担保する。
3. **カテゴリ未設定・未知カテゴリによるUIクラッシュ・表示欠落リスクの排除**:
   - `normalizeCategory`（`constants/categories.ts`）を活用し、旧カテゴリや空文字、未知カテゴリが含まれる場合でも「その他」等のフォールバックカテゴリに整然と分類され、アイテムが決して消滅・欠落しない堅牢な設計とする。
4. **空状態（Empty State）でのUX破綻リスクの排除**:
   - 買い物リスト全体が空の場合（補充不要）と、特定カテゴリで絞り込んだ結果該当アイテムがない場合（「このカテゴリには補充が必要なアイテムはありません」）の Empty State を明確に区別して表示する。

## 3. 要件定義 (Requirements)

1. **在庫管理画面（Stocks List）の追加ボタン整理**:
   - カテゴリフィルター横の「在庫を追加」ボタンに `hidden sm:flex` を適用。
   - モバイル（`< sm`）では非表示とし、右下FABに一本化。
   - デスクトップ（`sm:` 以上）では従来通り上部に表示。
2. **買い物リスト画面のカテゴリ絞り込み（フィルター）導線**:
   - 買い物リスト上部にカテゴリ切り替えピル（「すべて」「食品」「飲料」「日用品・消耗品」...）を配置。
   - 在庫一覧と同様の直感的なUIで、ワンタップでカテゴリ絞り込みができるようにする。
   - カテゴリ選択時、該当カテゴリのアイテム件数バッジを表示。
3. **買い物リスト画面のカテゴリ別セクション（グルーピング）表示**:
   - 「すべて」選択時、カテゴリごとに見出し（セクションヘッダー：カテゴリ名 ＋ 件数バッジ）を設け、グループごとにカードを並べる。
   - カテゴリの表示順は `STOCK_CATEGORIES` の標準順序に従う。
   - 特定カテゴリ選択時は、そのカテゴリのアイテムのみをすっきりと表示。
4. **ドメインコアロジックのモジュール化**:
   - `frontend/src/core/shoppingList.ts` に `groupShoppingListByCategory` などの純粋関数を実装。
   - Vitest 単体テスト `frontend/tests/core/shoppingList.test.ts` を作成。

## 5. 機能受け入れシナリオ (Given-When-Then)

### シナリオ 1: モバイル表示での在庫追加ボタン非表示とFAB動作
- **Given**: 幅 375px のモバイル画面で在庫管理画面を表示している
- **When**: 画面上部の検索バー直下を見る
- **Then**: カテゴリピル（すべて、食品、飲料...）が画面幅いっぱいに表示され、カテゴリ横の「在庫を追加」ボタンは非表示である
- **When**: 画面右下に固定配置された緑色のFAB（`+`）をタップする
- **Then**: 在庫追加モーダルが開き、新規在庫を登録できる

### シナリオ 2: デスクトップ表示での在庫追加ボタンの存続
- **Given**: 幅 1024px 以上のデスクトップ画面で在庫管理画面を表示している
- **When**: 画面上部のコントロールバーを見る
- **Then**: カテゴリピルの右横に「+ 在庫を追加」ボタンが表示されており、右下のFABは非表示である
- **When**: 「+ 在庫を追加」ボタンをクリックする
- **Then**: 在庫追加モーダルが開く

### シナリオ 3: 買い物リストのカテゴリ別グループ表示（「すべて」選択時）
- **Given**: 「食品」2件、「日用品・消耗品」1件の不足アイテムが存在する
- **When**: 買い物リストタブを選択し、カテゴリフィルター「すべて」が選択されている
- **Then**: 「食品 (2)」の見出しの下に食品2件のカードが表示され、「日用品・消耗品 (1)」の見出しの下に日用品1件のカードが表示される

### シナリオ 4: 買い物リストのカテゴリ絞り込み（特定カテゴリ選択時）
- **Given**: 「食品」2件、「日用品・消耗品」1件の不足アイテムが存在する
- **When**: 買い物リストタブ上部の「日用品・消耗品」カテゴリピルをタップする
- **Then**: 日用品・消耗品の1件のみが表示され、食品のアイテムは非表示となる

### シナリオ 5: 絞り込み後のアイテム0件時（Empty State）
- **Given**: 不足アイテムとして「日用品・消耗品」は存在するが、「医薬品」は0件である
- **When**: 買い物リストタブで「医薬品」カテゴリピルをタップする
- **Then**: 「医薬品には補充が必要なアイテムはありません」という親切なメッセージが表示される
