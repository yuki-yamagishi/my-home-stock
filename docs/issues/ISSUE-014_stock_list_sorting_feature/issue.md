## 1. 解決すべき課題・背景 (Why / Background)

1. **在庫一覧における表示順序の固定化と柔軟性の不足**:
   - 現在の在庫管理画面（「在庫」タブ）では、カテゴリ別の絞り込みと文字列検索のみが提供されており、表示順序はバックエンドから返却される「カテゴリ昇順・品名昇順」に固定されている。
   - 登録アイテム数が増加するにつれ、「賞味期限・消費期限が迫っている品目を優先してチェックしたい」「残量が少なくなっている品目（要補充）を上位に集めて補充状況を把握したい」「最近更新・登録したアイテムをすぐに確認したい」といった、ユーザーの多様な日常利用シナリオに柔軟に対応できていなかった。
2. **目的の在庫へのアクセスコスト削減**:
   - ソート順を変更できないことで、目的の在庫を探すために不要なスクロールや検索窓への入力が強いられていた。
   - 直感的に切り替えられる並び替え機能を導入することで、在庫把握・買い出し準備の体験を向上させる。

---

## 2. 排除するリスク (Risks to Eliminate)

1. **純粋ドメインロジックと UI 層の密結合・テスト漏れリスク**:
   - ソート処理を `App.tsx` 内の `useMemo` に直書きすると、複雑な比較ロジック（期限日未設定、4段階残量レベルと数量管理の比較、null/undefined）の単体テストが困難になり、将来の改修で回帰バグを誘発するリスクがある。
   - **対策**: `frontend/src/core/stockSort.ts` として純粋関数 `sortStockItems` を新設し、React / DOM 非依存のビジネスロジックとして 100% 単体テスト（Vitest）で保護する。
2. **期限日未設定（NULL）アイテムの並び順崩れリスク**:
   - 期限が近い順（昇順）において、期限未設定アイテムが先頭に紛れ込むと、期限が迫った重要品目が下に追いやられる。
   - **対策**: NULLS LAST 原則を厳格に適用し、期限未設定アイテムは昇順・降順ともに末尾に安定配置する。
3. **管理タイプ混在（残量レベル vs 数量管理）の不自然なソートリスク**:
   - 4段階残量管理（EMPTY〜FULL）と通常数量管理（個数・本数など）が混在する中で、適切な優先順位が定義されていないと不自然な並び順になる。
   - **対策**: 「残量が少ない順」では要補充（shortage）フラグが true のアイテムを最優先し、次いで残量スコア（0〜3）および実数量の昇順で並べる直感的な優先度ロジックを設計する。
4. **React 状態・配列の破壊的変更（Mutating）リスク**:
   - `Array.prototype.sort()` は元の配列を変更（インプレース破壊）するため、TanStack Query のキャッシュ配列を直接ソートすると意図しない挙動やバグを招く。
   - **対策**: `[...items].sort(...)` による非破壊ソートを徹底する。
5. **モバイル表示時のレイアウト崩れ・操作性低下リスク**:
   - スマートフォンの狭小画面において、検索バーやカテゴリタグ、在庫追加ボタンと干渉してレイアウトが崩れたり、操作しにくくなったりするリスク。
   - **対策**: 検索バーの横に Lucide アイコン付きのコンパクトな `<select>` セレクターを配置し、省スペースかつ直感的な操作感を実現する。

## 3. 受け入れ基準 (Acceptance Criteria / DoD)

- [x] **純粋ドメインソートロジックの実装**:
  - `frontend/src/core/stockSort.ts` を新設し、`sortStockItems(items, sortKey)` 純粋関数および `StockSortKey`, `STOCK_SORT_OPTIONS` を提供すること。
  - 以下の 7 種類のソート順をサポートすること：
    1. `category`: カテゴリ順（標準: カテゴリ昇順 → 品名昇順）
    2. `expiryAsc`: 期限が近い順（期限あり昇順 → 期限なし末尾 → 品名昇順）
    3. `expiryDesc`: 期限が遠い順（期限あり降順 → 期限なし末尾 → 品名昇順）
    4. `quantityAsc`: 残量が少ない順（要補充アイテム最優先 → 残量レベル/数量昇順 → 品名昇順）
    5. `quantityDesc`: 残量が多い順（残量レベル/数量降順 → 品名昇順）
    6. `nameAsc`: 名前順（品名昇順 `localeCompare('ja')`）
    7. `updatedDesc`: 更新が新しい順（`updatedAt` 降順 → `createdAt` 降順 → ID降順）
- [x] **単体テスト網羅**:
  - `frontend/tests/core/stockSort.test.ts` を作成し、各ソート順の正常系、期限未設定（null/undefined）、残量・数量混在、非破壊ソートの各ケースを 100% パスすること。
- [x] **UI 統合**:
  - `App.tsx` の在庫タブ上部に並び替え用セレクターを配置し、選択状態に応じて在庫一覧が即座に並び替わること。
  - 検索クエリやカテゴリ絞り込みとソートが連動して正常に機能すること。
- [x] **レスポンシブ対応**:
  - デスクトップおよびスマートフォンの両方でレイアウト崩れなく快適に操作できること。
- [x] **品質ゲート・規約準拠**:
  - `npm run check:fast`, `npm run test:related`, `npm run check:docs`, `npm run check` の全テスト・静的解析・型検査を通過すること。
  - 4 ドキュメント（`issue.md`, `pre_verification.md`, `plan.md`, `walkthrough.md`）の整合性が保たれていること。
