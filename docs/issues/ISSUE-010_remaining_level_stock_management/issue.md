## 1. 解決すべき課題・背景 (Why / Background)

家庭内の在庫管理において、調味料（塩、砂糖、マヨネーズ等）や日用品・消耗品（洗剤、シャンプー、ボディーソープ、トイレットペーパー等）の多くは以下の特性を持つ：

1. **常に1袋（1本・1ボトル）のみ常備・使用される**:
   - 複数ストックを持たず、1つ開封して使い切ったら買い足す運用が一般的である。
2. **グラム数や粒数を都度測量することは非現実的**:
   - 日常生活の中で「塩が残り150g」「洗剤が残り200ml」などと計量して入力することは著しく負荷が高い。
3. **現在の「個数管理（1個、2個...）」では残量が表現できない**:
   - 現状のシステムでは数量が「1」か「0」かしか表現できず、「1個」の状態でたっぷりあるのか、底をつきかけていて今週末に買い足すべきなのかが把握できない。
   - その結果、「まだ1個あると思って買いに行かなかったら料理の途中で切れた」「もう無いと思って買ってきたら半分以上残っていた」という買い忘れ・重複購入のトラブルが多発している。

これを解決するため、測量不要で直感的に残量を記録できる「4段階残量管理（十分、まだまだ、怪しい、すっからかん）」を導入し、ワンタップでのステータス更新および買い物リストとの自動連携を実現する。

---

## 2. 排除するリスク (Risks to Eliminate)

1. **既存の個数管理アイテムの破壊リスク（後方互換性破壊の防止）**:
   - 既に登録されている個数管理アイテム（牛乳 2本、缶詰 5個など）のデータや表示・操作性を一切損なわないこと。デフォルトを `QUANTITY` とし、既存のデータ・API 契約を 100% 維持する。
2. **OpenAPI 型定義と DB スキーマの不整合リスク（型安全性喪失の防止）**:
   - バックエンドのエンティティ、マイグレーション、DTO、OpenAPI 仕様書（`docs/openapi.json`）、フロントエンド型定義（`schema.d.ts`）に Enum（`StockType`, `RemainingLevel`）を正しくバインドし、型乖離や実行時エラーを排除する。
3. **楽観的排他制御のバイパスリスク（同時更新時のデータ上書き防止）**:
   - カード上のワンタップ残量変更や買い物リストでの「補充完了」ボタンにおいても、必ずエンティティの `@Version` を検証し、複数端末での競合（409 Conflict）を検知してデータ先祖返りを防止する。
4. **世帯分離（マルチテナント）漏れリスクの排除**:
   - 買い物リスト抽出クエリや更新処理において、必ず `household_id` で厳格にスコープを限定し、他世帯のデータが混入しないことを保証する。

## 3. 要件定義 (Requirements)

1. **在庫管理タイプ（`StockType`）の導入**:
   - `QUANTITY`: 従来の個数カウント管理（数量 `quantity` + 単位 `unit` + 下限閾値 `minThreshold`）。
   - `REMAINING_LEVEL`: 残量段階管理（4段階の残量レベル `remainingLevel` + 単位 `unit`）。
2. **4段階残量レベル（`RemainingLevel`）の定義**:
   - `FULL`: 「十分」（たっぷりある・新品〜7割以上）/ 表示色: エメラルド
   - `PLENTY`: 「まだまだ」（余裕あり・半分程度）/ 表示色: ブルー
   - `LOW`: 「怪しい」（残りわずか・そろそろ買いたい）/ 表示色: アンバー
   - `EMPTY`: 「すっからかん」（なし・底をついた）/ 表示色: ローズ
3. **買い物リスト（不足品）との自動連携**:
   - 残量管理アイテムの残量が `LOW`（怪しい）または `EMPTY`（すっからかん）になった場合、自動的に買い物リストにリストアップされる。
   - 買い物リスト上のアクションとして、「補充完了 (十分にする)」ボタンを提供し、押下時に一発で `FULL` へ復帰させリストから解消する。
4. **クイック追加フォーム & 編集モーダルの拡張**:
   - 「個数で管理」「残量で管理」の切り替えタブ/セグメントを配備。
   - 残量管理選択時、数量・閾値入力欄が非表示になり、タップしやすい4段階残量ボタングループ（十分・まだまだ・怪しい・すっからかん）を表示。
5. **在庫一覧カードでのワンタップ操作**:
   - 残量管理アイテムのカード上に、現在の残量ゲージおよび4段階のボタングループ（またはクイック切り替えボタン）を表示。
   - 詳細編集モーダルを開かなくても、一覧カード上で直接ワンタップで残量を変更可能にする。
   - 「消費 (-1)」操作時は残量を1段階下げる（FULL → PLENTY → LOW → EMPTY）。

## 4. 技術設計・実装方針 (Technical Notes / Design)

- **DB スキーマ (Flyway V3)**:
  - `ALTER TABLE stock_items ADD COLUMN stock_type VARCHAR(20) NOT NULL DEFAULT 'QUANTITY';`
  - `ALTER TABLE stock_items ADD COLUMN remaining_level VARCHAR(20);`
  - `CREATE INDEX IF NOT EXISTS idx_stock_items_stock_type ON stock_items(household_id, stock_type);`
- **バックエンド (Spring Boot 4)**:
  - `StockType` Enum (`QUANTITY`, `REMAINING_LEVEL`)
  - `RemainingLevel` Enum (`EMPTY`, `LOW`, `PLENTY`, `FULL`)
  - `StockItemRepository`: `findShortageItemsByHousehold` クエリを拡張し、`((s.stockType = 'QUANTITY' AND s.quantity <= s.minThreshold) OR (s.stockType = 'REMAINING_LEVEL' AND s.remainingLevel IN ('LOW', 'EMPTY')))` とする。
  - `StockItemService`: `consumeStockItem` において `REMAINING_LEVEL` の場合は残量を1段階下げる。
- **フロントエンド (React 18 + TypeScript Strict)**:
  - `frontend/src/core/stockStatus.ts`: `isShortage` に `stockType` と `remainingLevel` の判定を追加。残量レベルの表示メタデータ（ラベル・色・アイコン）を提供。
  - `frontend/src/components/stock/EditStockModal.tsx`: 管理種別の切り替えと4段階ボタングループの実装。
  - `frontend/src/App.tsx`: クイック追加フォーム、在庫カード、買い物リストカードの残量対応。

## 5. 受け入れ基準 (Acceptance Criteria & DoD)

### 5.1. 機能受け入れシナリオ (Given-When-Then)

- **シナリオ 1: 残量管理アイテムの登録**:
  - **Given**: クイック追加フォームで管理方法に「残量で管理」を選択している。
  - **When**: 品名「マヨネーズ」、カテゴリ「食品」、残量「十分」を選択して「追加する」をクリックする。
  - **Then**: `stockType: 'REMAINING_LEVEL'`, `remainingLevel: 'FULL'` で登録され、一覧に「十分」バッジ付きのカードが表示される。
  - **And**: 買い物リストには表示されない。

- **シナリオ 2: カード上でのワンタップ残量変更と買い物リスト入り**:
  - **Given**: 在庫一覧に「マヨネーズ（残量: 十分）」が表示されている。
  - **When**: カード上の「怪しい」ボタンをクリックする。
  - **Then**: 残量が即座に「怪しい」に更新され、買い物候補（不足）のバッジ件数が 1 件増加する。
  - **And**: 買い物リストタブを開くと「マヨネーズ（現在: 怪しい）」が表示されている。

- **シナリオ 3: 買い物リストでの補充完了（十分にする）**:
  - **Given**: 買い物リストに「マヨネーズ（現在: 怪しい）」が表示されている。
  - **When**: 「補充完了 (十分にする)」ボタンをクリックする。
  - **Then**: 残量が「十分」に更新され、買い物リストから当該アイテムが解消されて一覧から消える。

- **シナリオ 4: 消費操作による段階的残量降下**:
  - **Given**: 在庫一覧に「洗剤（残量: 十分）」が存在する。
  - **When**: 「消費」ボタンをクリックする。
  - **Then**: 残量が 1 段階下がって「まだまだ」に更新される。
  - **When**: さらに「消費」ボタンをクリックする。
  - **Then**: 残量が 1 段階下がって「怪しい」に更新され、買い物リストに追加される。

- **シナリオ 5: 編集モーダルでの残量変更および管理方法の切り替え**:
  - **Given**: 「マヨネーズ」の詳細編集モーダルを開いている。
  - **When**: 残量を「すっからかん」に変更して「更新する」をクリックする。
  - **Then**: 楽観排他バージョンが検証されて保存され、一覧の表示が「すっからかん」に更新される。

- **シナリオ 6: 個数管理アイテムの既存動作維持（後方互換性保証）**:
  - **Given**: 従来の個数管理アイテム「牛乳（数量: 2本, 基準: 1本）」が存在する。
  - **When**: 「-」ボタンを押して数量を 1本 に減らす。
  - **Then**: 数量が 1本 に更新され、基準値以下となったため買い物リストに追加される。従来の個数管理フローが一切壊れていない。
