- **ステータス**: 🟣 進行中 (`status: in-progress`)
- **作成日**: 2026-09-17

---

## 1. 4軸事前検証サマリー

### 1.1. 技術的制約
- **React コンポーネント構造・JSXの整合性**:
  - `App.tsx` 内で、現在 `<main>` 直下に無条件で配置されているメトリックカード群（`<div className="grid grid-cols-2 sm:grid-cols-4 gap-3 sm:gap-4">...</div>`）を、`{activeTab === 'stocks' && ( ... )}` の内側に配置する。
  - 親要素 `<main className="... space-y-6">` の垂直スペーシング（`space-y-6`）が、買い物タブおよび期限タブでメトリックカードが消えた際にも自然な余白を維持することを確認。
- **計算パフォーマンス・再レンダリング**:
  - `summary`（`calculateStockSummary(allStocks)`）の計算はヘッダーやボトムナビのバッジ件数表示にも使われているため、`useMemo` の計算自体はそのまま維持する。

### 1.2. UX・エッジケース
- **ファーストビューでの一覧性向上**:
  - スマートフォン（縦幅 667px〜844px 程度）において、メトリックカード（高さ約 180px〜200px）が消えることで、買い物リストのファーストビューで 2〜3 個以上のアイテムカードが即座に視界に入り、親指での操作性が劇的に改善される。
- **在庫タブのダッシュボード性維持**:
  - 在庫タブでは全体を俯瞰できるようカード群を維持。

### 1.3. データ永続性・互換性
- **API・スキーマへの影響ゼロ**:
  - バックエンド API、JPA エンティティ、OpenAPI スキーマ等への影響は一切ない純粋なフロントエンド表示制御の改修。

### 1.4. テスト自律性
- **型検査とビルド検証**:
  - `npm.cmd run check:fast` および `npm.cmd run check` により、JSX 構文・型安全性を機械的に担保可能。

## 2. 重複・パッチワーク点検 (Impact & Duplication Check)

### 2.1. 既存コードベース・ユーティリティの横断調査
- **`App.tsx` のタブ構造**:
  - `activeTab` は `'stocks' | 'shopping' | 'expiring'` のユニオン型で管理されている。
  - メトリックカードを在庫タブのコンテナ内に移動するだけの最小・クリーンな変更であり、新たな状態管理や重複コードは発生しない。

### 2.2. 車輪の再発明・つぎはぎ改修の防止
- **条件付きレンダリングの局所化**:
  - CSS クラスで `hidden` を付け外しするのではなく、React の条件付きレンダリング `{activeTab === 'stocks' && ...}` に集約することで、DOM ツリーの不要なノード生成を抑止する。
