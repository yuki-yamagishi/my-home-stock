# [ISSUE-013] 買い物・期限タブにおけるメトリックカード非表示化（一覧性・視認性最適化）

* **ステータス**: ✅ `status: closed`
* **種別**: 🎨 `type: ui/ux` / 🟢 `type: feature`
* **担当者**: AIエージェント
* **作成日**: 2026-09-17
* **関連 GitHub Issue / PR**: PR #18 / [GitHub Issue #24](https://github.com/yuki-yamagishi/my-home-stock/issues/24)

---

## 1. 解決すべき課題・背景 (Why / Background)

1. **特定作業タブにおけるメトリックカードの冗長性と縦領域圧迫**:
   - アプリケーション画面上部に配置されている 4 枚のメトリックカード（「総登録品目」「買い物候補 (不足)」「期限間近 (7日以内)」「期限超過」）は、現在すべてのタブ（在庫・買い物・期限）で常時表示されている。
   - しかし、ナビゲーション（デスクトップヘッダーのタブおよびモバイルのボトムナビ）には既に「買い物候補件数」および「期限間近・超過件数」のバッジが表示されており、タブ内見出しやカテゴリピルにも件数バッジが存在する。
   - 特に「買い物」タブ（買い出し中）や「期限」タブ（期限チェック中）において、画面上部に大きなカード群が居座っていることで、スマートフォン等の限られた画面でファーストビューが圧迫され、肝心のアイテム一覧が下に追いやられて不要なスクロールを強いられていた。

2. **タブの目的に応じたレイアウト最適化**:
   - 「在庫」タブは全在庫の状況を俯瞰・管理するダッシュボードとしての役割を持つため、4 枚のサマリーカードは有用である。
   - 一方で、「買い物」タブおよび「期限」タブは買い出しや廃棄防止という具体的なアクションを実行する「作業リスト画面」であるため、上部カードを非表示にして一覧性を最大化することが求められる。

---

## 2. 排除するリスク (Risks to Eliminate)

1. **在庫タブにおける全体把握性・サマリー情報の喪失リスクの排除**:
   - 買い物タブ・期限タブでカードを非表示にする一方で、在庫タブ（`stocks`）では 4 枚のメトリックカードを確実に維持し、総登録数や全体状況の把握性を損なわないようにする。
2. **コンポーネント構造の破壊・スタイルの崩れリスクの排除**:
   - メトリックカードを `<main>` 直下から `{activeTab === 'stocks' && ( ... )}` 内へ安全に移動し、Tailwind CSS の余白（`space-y-6` 等）やレスポンシブグリッド（`grid-cols-2 sm:grid-cols-4`）のレイアウト整合性を担保する。
3. **タブ切り替え時のちらつきや状態不整合リスクの排除**:
   - タブ切り替え時に不要な再計算やレイアウトシフトが生じないよう、既存の `summary`（`calculateStockSummary`）の計算フローを維持する。

---

## 3. 要件定義 (Requirements)

1. **メトリックカードの表示制御**:
   - メトリックカード（総登録品目、買い物候補、期限間近、期限超過）を「在庫」タブ（`activeTab === 'stocks'`）でのみレンダリングする。
   - 「買い物」タブ（`activeTab === 'shopping'`）および「期限」タブ（`activeTab === 'expiring'`）ではメトリックカードをレンダリングしない。
2. **ファーストビューの最大化**:
   - 買い物タブおよび期限タブを開いた際、画面最上部から直ちにヘッダー・カテゴリピル・アイテム一覧が表示されるようにする。

---

## 4. 受け入れ基準 (Acceptance Criteria)

- [x] 在庫タブ（`stocks`）選択時、画面上部に 4 枚のメトリックカード（総登録品目、買い物候補、期限間近、期限超過）が表示されること
- [x] 買い物タブ（`shopping`）選択時、4 枚のメトリックカードが非表示となり、最上部に買い物リストのヘッダー・カテゴリピルが表示されること
- [x] 期限タブ（`expiring`）選択時、4 枚のメトリックカードが非表示となり、最上部に期限管理のヘッダー・アイテム一覧が表示されること
- [x] デスクトップ表示（幅 1024px 以上）およびモバイル表示（幅 375px）の双環境でレイアウトが崩れないこと
- [x] `npm.cmd run check`（型検査、単体テスト、ドキュメント整合性、プロダクションビルド）に全件合格すること

---

## 5. 機能受け入れシナリオ (Given-When-Then)

### シナリオ 1: 在庫タブでのメトリックカード表示
- **Given**: アプリケーションを開き、在庫タブ（`stocks`）が表示されている
- **When**: 画面上部を見る
- **Then**: 「総登録品目」「買い物候補 (不足)」「期限間近 (7日以内)」「期限超過」の 4 枚のカードが表示されている

### シナリオ 2: 買い物タブでのメトリックカード非表示とファーストビュー
- **Given**: 在庫タブを表示している
- **When**: ナビゲーションの「買い物」タブをタップ（クリック）する
- **Then**: 4 枚のメトリックカードが非表示となり、画面最上部に「買い出しが必要なアイテム (不足・残りわずか)」およびカテゴリピルが表示される

### シナリオ 3: 期限タブでのメトリックカード非表示とファーストビュー
- **Given**: 買い物タブを表示している
- **When**: ナビゲーションの「期限」タブをタップ（クリック）する
- **Then**: 4 枚のメトリックカードが非表示となり、画面最上部に「賞味・消費期限が近いアイテム (7日以内 / 期限切れ)」および期限切れアイテム一覧が表示される
