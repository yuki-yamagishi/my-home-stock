# [ADR-0008] 4ドキュメントIssue管理・モジュール式チェッカー・独立AIレビューによる開発ガバナンスハーネスの導入

* **ステータス**: 承認済
* **日付**: 2026-09-06
* **決定者**: プロジェクトオーナー, 開発チーム

---

## 1. 文脈と問題提起 (Context)

自律型 AI エージェントおよび人間開発者による MyHomeStock プロジェクトの進行において、以下のガバナンスおよび開発者体験上の課題が顕在化していた：

1. **ドキュメントの肥大化と過去ログ上書き喪失**:
   - `docs/pre_phase_verification.md` や `docs/walkthrough.md` に全フェーズの記録を追記し続けると、ファイルサイズが急増してトークン消費を圧迫し、過去の設計決定や検証エビデンスが最新作業で上書き・喪失するリスクがあった。
2. **実装者バイアスによるレビュー漏れ**:
   - 実装を担当したエージェント自身が品質検証を行うと、不要な差分や規約違反、エッジケースのテスト漏れを見落としやすい。
3. **ローカル検証漏れによるブロークンコードの混入**:
   - コミット時やプッシュ時に自動ガードがないと、秘密情報（APIキー等）の混入や、型エラー・テスト失敗コードがリモートへプッシュされる危険があった。
4. **レビュー運用の属人化**:
   - PR レビューにおいて重要度（修正必須か、単なる提案か）が標準化されていないと、人間レビュアーの認知負荷が高まる。

---

## 2. 決定内容 (Decision)

先行リポジトリ `job-eval` で実証されたベストプラクティスを取り入れ、以下のガバナンスハーネスを正式採用する：

1. **Issue ライフサイクルの 4 ドキュメント・フォルダ完結化**:
   - `docs/issues/ISSUE-XXX_<title>/` を単位とし、以下の 4 ドキュメントでタスクライフサイクルを完結させる：
     - `issue.md`: 要件定義、背景、受け入れ基準
     - `pre_verification.md`: 4軸事前検証ログ（技術的制約、UX、永続性、テスト自律性）
     - `plan.md`: 実装計画・変更対象ファイル一覧
     - `walkthrough.md`: 成果レポート・動作検証エビデンス
   - ルート `docs/` 配下は最新進行中 Issue へのポインタとして維持し、トークン消費を最小化する。
2. **AI 独立レビューサブエージェント（Fleet Reviewer）の導入**:
   - `.agents/subagents/fleet-reviewer/` に最小権限サブエージェント（コード変更・プッシュ禁止、読み取り・テスト実行・PRコメント投稿のみ許可）を配備。
   - **Conventional Comments**（`[must]`, `[should]`, `[imo]`, `[nits]`, `[ask]`）および判定（`[LGTM]` / `[要修正]`）を強制し、客観的第三者コードレビューを実施。
   - 自動マージを禁止し、人間開発者の明示的なレビュー・承認を経てマージする。
3. **モジュール式チェッカー群 (`scripts/checkers/`) への責務分割**:
   - `issueDocChecker.js`: 4 ドキュメントおよびルートポインタ整合性検証。
   - `adrChecker.js`: ADR 採番・目次テーブル登録検証。
   - `agentSkillChecker.js`: AGENTS.md およびスキル定義の同期検証。
   - `docCheck.js` はこれらを統括する軽量オーケストレーターとする。
4. **共有 Git Hooks (`.githooks/`) による物理的ガード**:
   - `pre-commit`: シークレットスキャン（`securityCheck.js`）およびドキュメント整合性（`docCheck.js`）。
   - `pre-push`: ワンショット総合品質ゲート（`npm.cmd run check`）。
   - `git config core.hooksPath .githooks` により開発環境全体で統一。

## 3. 結果・影響 (Consequences)

### プラスの影響 (Positive)
- **過去ログ・知見の完全保全**: 各 Issue の検証ログや成果レポートが永続的に残り、将来の保守・機能拡張時の参照が容易。
- **品質と安全性の自動担保**: 秘密情報のコミットやブロークンコードのプッシュが物理的に遮断される。
- **AI-Human 協調の円滑化**: Fleet Reviewer が客観的指摘を行い、人間レビュアーは本質的な設計・仕様確認に集中可能。

### トレードオフ・留意点 (Neutral / Negative)
- コミットおよびプッシュ時に検証スクリプトが自動実行されるため、数秒のオーバーヘッドが発生する（ただし品質担保の観点から許容される）。
